# Архитектура MVP

## Компоненты

- **Telegram Bot Core**
  - Обрабатывает команды `/start`, `/help`, `/status`, `/cancel`.
  - Валидирует доступ пользователя.
  - Запускает быстрый подсчет объема выборки.
  - Ставит задачу анализа в одиночный режим на пользователя.

- **KAD API Adapter**
  - Абстракция над провайдером `parser-api.com/kad-arbitr-ru`.
  - Поддерживает быстрый подсчет количества дел и выборку списков дел.
  - Политики ретраев: `429` (пауза 60 сек, 3 повтора), `503/timeout` (2 повтора, затем ошибка пользователю).

- **Analysis Engine**
  - Статистический расчет исходов (удовлетворено/отказано).
  - Выделение топ-2 оснований для удовлетворения и отказа.
  - Формирование итоговой сводки и файла `.txt`.

- **Cache Layer**
  - TTL 24 часа.
  - Хранит итоговый анализ в SQLite.

- **Access Control**
  - Список пользователей, которым разрешен доступ к боту.
  - Управление через админку.

- **Admin API**
  - Настройка глубины поиска.
  - Управление списком разрешенных пользователей.
  - Просмотр и редактирование промпта анализа (используется при подключении LLM).

## Поток запроса

1. Пользователь отправляет запрос.
2. Бот проверяет доступ и лимит.
3. Бот делает быстрый запрос подсчета количества дел.
4. В зависимости от результата:
   - `0` — возвращает сообщение об отсутствии дел.
   - `>50` — предлагает выбрать квартал (`1..4`) и запускает анализ выбранного периода.
   - `1-50` — запускает анализ и сообщает оценку времени.
5. После анализа бот отправляет сводку и файл `.txt`.

## Ограничения и SLA

- Одна активная задача на пользователя.
- До 50 уникальных пользователей в день.
- Uptime 95% в рабочие часы (Пн-Пт, 9:00-18:00 МСК).

## Хранение и безопасность

- Логи содержат текст запроса и итоговый результат.
- Telegram ID в логах заменяется на хэш.
- Данные технические и анонимные, явное согласие не требуется.
