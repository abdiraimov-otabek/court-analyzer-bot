# Интеграция с parser-api.com (arbitr_api)

В проекте используется адаптер `ParserApiKadClient` для `parser-api.com/parser/arbitr_api`.

## Конфигурация

Переменные окружения:

- `KAD_API_BASE_URL` (по умолчанию `https://parser-api.com/parser/arbitr_api`)
- `KAD_API_KEY`

## Используемые эндпоинты

- `/search` — поиск дел с пагинацией.
- `/details_by_id` — получение деталей дела по `CaseId`.
- `/details_by_number` — получение деталей по номеру дела (используется, если в запросе найден номер дела).

## Ожидаемый формат ответа (важные поля)

### `/search`

- `Success` (1/0)
- `PagesCount`
- `Cases` — список дел, каждое дело содержит `CaseId`.

### `/details_by_id`

- `Success` (1/0)
- `Cases` → `CaseNumber`, `CaseInstances` → `InstanceEvents`

Из событий извлекаются:
- дата (`Date`)
- текстовые поля (`EventTypeName`, `DecisionTypeName`, `EventContentTypeName`, `Comment`) для определения исхода и оснований.

## Нормализация результата

- Исход определяется по наличию слов `удовлетвор` или `отказ` в текстовых полях.
- Основания извлекаются по словарю ключевых фраз (см. `ReasonExtractor`).

## Парсинг запроса

`QueryParser` извлекает из текста:

- год/квартал (формирует `DateFrom`/`DateTo`)
- ИНН (10-12 цифр) или короткое название как `Inn`
- номер дела вида `А00-0000/0000`
- суд (минимальный словарь, например `9 ААС` → `9 арбитражный апелляционный суд`, `АС Москвы` → `АС города Москвы`)
- тип дела (`CaseType`) по ключевым словам (банкротство/административное/гражданское)

Если формат ответа на стороне провайдера отличается — адаптер нужно скорректировать.
